# Сервис управления заказами

---

## 1. Цель проекта

Создать лаконичный микросервис на **Java Spring Boot** с **JWT-аутентификацией**, ролевым доступом и CRUD-функционалом для управления пользователями и заказами.

Проект предназначен для демонстрации:

* **архитектуры REST API**
* **Spring Security + JWT**
* **работы с PostgreSQL 17**
* **миграций БД с Liquibase**
* **Docker / Docker Compose**
* **Unit тестирования**

---

## 2. Функциональные требования

### 2.1. Структура базы данных

#### Таблица `users`

| Поле     | Тип    | Описание                 |
| -------- | ------ | ------------------------ |
| id       | UUID   | Уникальный идентификатор |
| username | String | Логин (уникальный)       |
| password | String | Зашифрованный пароль     |
| role     | Enum   | `USER`, `ADMIN`          |

#### Таблица `orders`

| Поле        | Тип           | Описание                              |
| ----------- | ------------- | ------------------------------------- |
| id          | UUID          | Уникальный идентификатор              |
| user_id     | UUID          | Владелец заказа (FK → users.id)       |
| description | String        | Описание заказа                       |
| status      | Enum          | `CREATED`, `IN_PROGRESS`, `COMPLETED` |
| created_at  | LocalDateTime | Дата создания                         |

#### ***Тестовые пользователи***

Для быстрого старта работы с API в базе данных предварительно созданы два тестовых пользователя:

| username     | role  | password  |
| ------------ | ----- | --------- |
| SUPER_ADMIN  | ADMIN | rootroot  |
| SIMPLE_USER  | USER  | password  |

> **Как создаются:** Эти пользователи автоматически добавляются при выполнении Liquibase-миграций во время инициализации базы данных.

## 3. API эндпоинты

### 3.1. Аутентификация (Spring Security + JWT)

| Метод | URL                  | Описание                                            |
| ----- | -------------------- | --------------------------------------------------- |
| POST  | `/api/auth/register` | Регистрация пользователя (роль `USER` по умолчанию) |
| POST  | `/api/auth/login`    | Аутентификация, возвращает JWT                      |
| GET   | `/api/auth/me`       | Информация о текущем пользователе                   |

> **Важно:** для запуска приложения требуется переменная окружения `JWT_SECRET` в Base64.  
> Пример генерации 32-байтного секрета:

```bash
openssl rand -base64 32 
```

---

### 3.2. Пользователи (только `ADMIN`)

| Метод  | URL               | Описание                           |
| ------ | ----------------- | ---------------------------------- |
| GET    | `/api/users`      | Получить список всех пользователей |
| DELETE | `/api/users/{id}` | Удалить пользователя               |

> **Примечание:** эти операции доступны только пользователям с ролью `ADMIN`.  
> Для тестирования можно использовать `SUPER_ADMIN` (password: `rootroot`).

---

### 3.3. Заказы

| Метод  | URL                | Доступ        | Описание                     |
| ------ | ------------------ | ------------- | ---------------------------- |
| POST   | `/api/orders`      | USER / ADMIN  | Создать заказ                |
| GET    | `/api/orders`      | USER / ADMIN  | Заказы текущего пользователя |
| GET    | `/api/orders/all`  | ADMIN         | Все заказы                   |
| PUT    | `/api/orders/{id}` | ADMIN         | Обновить статус заказа       |
| DELETE | `/api/orders/{id}` | OWNER / ADMIN | Удалить заказ                |

> **Примечание:** `OWNER` — это пользователь, который создал заказ.  
> ADMIN может управлять всеми заказами.

## 5. Сборка и запуск приложения

Приложение и база данных поднимаются вместе через Docker Compose.

#### 1. Создайте файл `.env` в корне проекта и добавьте туда переменную `JWT_SECRET` в Base64:

```bash
# .env
JWT_SECRET=ваш_32_байтный_секрет_в_base64
```

Пример генерации 32-байтного секрета:

```bash
> openssl rand -base64 32
```

> **Важно:** использование `.env` файла позволяет хранить секреты отдельно от исходного кода.  
> Docker Compose автоматически подставит переменные окружения из `.env` в контейнер приложения.  
> Например, в `docker-compose.yml` это делается так:
>
> ```yaml
> environment:
>   JWT_SECRET: ${JWT_SECRET}
> ```
>
> Здесь `${JWT_SECRET}` будет заменён на значение из вашего `.env` файла при запуске контейнеров.



#### 2. Запустите контейнеры (DB и application):

```bash
docker-compose up --build
```
